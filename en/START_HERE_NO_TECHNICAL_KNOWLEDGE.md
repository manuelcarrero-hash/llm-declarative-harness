# Start here if you have no technical knowledge

You do not need to know programming or understand artificial-intelligence terminology to use this harness.

## What is it?

This harness is a folder containing instructions and formats that help an artificial intelligence work more methodically on large projects.

It works like an operating manual for the AI. It explains how to define what must be achieved, preserve progress, review the work, continue in another conversation and decide when a task is truly finished.

It is not another AI and it is not an application you need to install. It is a set of rules you can share with a model that can consult files and work on projects.

## What problems does it help prevent?

This harness may help if any of these have happened to you:

- The AI forgot decisions you had already made.
- You opened a new conversation and had to explain everything again.
- The model said it was finished, but you later found errors or pending work.
- You did not know which file or version was correct.
- Several agents worked, but it was unclear who did what.
- The project grew and you no longer knew its exact state or next step.
- You changed models and lost your way of working.
- The AI changed something you had not authorized.

## What is it for?

It helps the AI:

- understand the project objective and how to prove it was achieved;
- follow clear rules and respect your boundaries;
- maintain an updated document with progress and pending work;
- review the work before declaring it finished;
- transfer the project correctly to another agent or conversation;
- distinguish between something created, tested, published and validated by a person;
- explain honestly what it can and cannot do on its platform.

## When should you use it?

Use it for work that:

- will take several conversations or days;
- has many stages or files;
- you do not want to explain again from the beginning;
- may have consequences if left incomplete;
- needs review, testing or human approval;
- will be handled by different AIs;
- you want to continue in ChatGPT, Claude, Gemini, Codex or another platform.

Examples:

- developing or improving an application;
- writing a book, course or extensive research project;
- building a website or digital product;
- preparing a professional project with several deliverables;
- coordinating several agents to analyze, create and review work;
- maintaining a personal project for weeks or months.

## When do you not need it?

You probably do not need it to:

- ask a simple question;
- summarize or translate a short text;
- draft a message or email;
- generate a quick idea;
- complete a small task in one conversation;
- do work where maintaining these documents would take longer than the task itself.

## How to begin

### Step 1. Give access to the harness

If the platform cannot yet read this folder, share the link, connect Drive, attach the files or place them in the project. This is the only preparation step that may depend on the platform.

### Step 2. Choose one of these three instructions

#### Start a new project

> I want to start a project using this harness. Guide me in plain language. Ask what I want to achieve and where state should be preserved; verify your own capabilities and select only the necessary modules. Before creating files or acting, show me what you will do and which authorizations you need. Do not ask me to configure technical files.

#### Continue an existing project

> I want to continue this project using the harness. First locate the authoritative state and sources of truth. Explain where we are, what is verified and the next action. If state does not exist or you find contradictory versions, do not invent or overwrite: propose how to reconstruct it or resolve the conflict and request authorization before writing.

#### Check whether the work is truly finished

> Check whether this work is truly finished. Begin in read-only mode and compare the real outcome against every completion criterion. Distinguish what was created, reviewed, published or deployed and validated by a person. Identify every open gate and use only the harness terminal states. Do not fix anything until I authorize it.

### Step 3. Answer in ordinary language

The model should ask only what it needs to resolve:

- what you want to achieve and how a finished result will be recognized;
- whether project state exists and where it should be preserved.

The model must verify and explain its own capabilities. It must not ask you to select modules, complete YAML, edit Markdown or configure technical paths.

### Step 4. Review the startup summary

Before acting, the model should explain in plain language:

- what it understood;
- where it found or proposes to store state;
- what it can do and what it could not verify;
- which modules it selected and why;
- what its first action will be;
- which decisions or permissions it needs from you.

### Step 5. Authorize only what is necessary

The harness does not automatically grant permission to publish, deploy, delete information, change access, spend money or send communications. You remain in control.

## The most important point

The harness helps organize work, but it does not make an AI infallible. It also does not provide tools that the platform lacks. Its purpose is to make visible what the model knows, what it did, what it verified and what remains open.

If the model cannot create agents, consult files, measure its context or open another session, it must say so and adapt the process without pretending to perform those functions.

## After this guide

You do not need to read or configure the technical files. The model should begin with `00_READ_ME_FIRST.md`, apply `01_core/GUIDED_START.md` and use only the modules needed for your project.
