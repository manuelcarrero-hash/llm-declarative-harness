# Exploratory cross-platform runs — 2026-08-29

## Scope

Three real runs of the same general scenario: a `NEW` document project to research and draft a transfer-pricing news article using Harness v0.4.0. Evidence was preserved through user-provided screenshots.

These runs are exploratory. They are not certification, a statistical benchmark or a general provider evaluation. Model, platform and some later interactions varied; the runs are useful for detecting protocol failure modes.

## Observed results

| Environment | Result | Strengths | Material deviations |
| --- | --- | --- | --- |
| ChatGPT outside Work | Partially conformant, high quality | Real checkpoints, source selection and exclusions, editorial reconstruction, evidence matrix, inferential caution | Excess ceremony, repetition and empty confirmations; poor mobile table rendering |
| Claude | Partially conformant | Clear load, classification and receipt; concise experience | Less observable evidence for research, reconstruction and checkpoints; initial confusion between prior state and references |
| Gemini Flash | Non-conformant in the observed run | Identified manifest, version and mode | Omitted state location from minimum questions, claimed modules/capabilities without sufficient proof and drafted before closing evidence and its declared authorization gate |

## Changes derived for v0.4.1

1. Default `COMPACT` mode with a normal 250-word checkpoint budget; `AUDITABLE` on request or need.
2. Automatic continuation between authorized checkpoints; pause only for a decision, risk, contradiction or new authority.
3. Minimum observable output per module; naming or reading it does not prove application.
4. Capability demonstrated through a current action or honestly degraded.
5. No premature drafting for work based on current facts.
6. Separate prior state, reusable materials and style references.
7. Explicit distinction between in-chat operational state and durable state.
8. Mobile-friendly representation without wide tables by default.
