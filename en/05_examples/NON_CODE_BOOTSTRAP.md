# Bootstrap Example for a Non-Code Project

Request: “Help me write a course about negotiation. I want to research, draft, review and prepare it for publication without losing decisions between conversations.”

## Workflow translation

| In software | In writing or research |
| --- | --- |
| Implementation | Draft or content development |
| Diff | Changes between versions |
| Tests | Source, structure, requirement and coherence checks |
| Reviewer | Editor, academic reviewer or critic |
| Bug | Inconsistency, reasoning gap or unsupported claim |
| Deploy | Publication or delivery |
| User-validated | Approval by the author, client or academic owner |

## Execution

1. The agent reads the harness and declares actual capabilities.
2. It identifies the project, audience, deliverables, existing sources and prior decisions.
3. It creates a contract with scope, expected outline, quality criteria, permitted sources, boundaries and an observable completion condition.
4. It maintains `PROJECT_STATUS.md` with validated chapters or modules, pending drafts, editorial decisions, risks and the next action.
5. The author or researcher produces a bounded draft and records sources and assumptions.
6. A reviewer inspects the actual draft against audience, structure, accuracy, evidence and editorial criteria; the reviewer returns `APPROVED` or `CHANGES_REQUIRED`.
7. Comments become traceable changes. A resolved comment does not mean the content was published.
8. If the session changes, create a handoff containing the latest authoritative draft, decisions, sources, open comments and the successor's first action.
9. Declare `ACHIEVED` only when every deliverable is complete, reviewed and approved by the authorized person. Publication requires separate authority.

Without an independent reviewer, record the review as non-independent adversarial review. Without verifiable source access, label claims `REPORTED` or `UNKNOWN`, not verified.
