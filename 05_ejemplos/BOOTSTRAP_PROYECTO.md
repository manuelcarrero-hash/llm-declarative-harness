# Ejemplo de bootstrap

Solicitud: “Continúa este proyecto, corrige el flujo de registro y deja evidencia verificable”.

1. El agente lee el arnés y declara capacidades.
2. Identifica repositorio, rama, estado y reglas efectivas.
3. Crea un contrato: flujo corregido, pruebas relevantes, revisión y validación observable.
4. El lead asigna implementación; el builder devuelve diff y pruebas.
5. El reviewer inspecciona el diff real y emite veredicto.
6. El lead integra y actualiza estado autorizado.
7. Si cambia la sesión, se genera handoff y el sucesor realiza handshake.
8. Sólo se declara `ACHIEVED` cuando todos los gates pasan.

Si la plataforma no dispone de agentes separados, el paso 5 se registra como revisión adversarial no independiente y el objetivo no debe atribuirse una aprobación independiente inexistente.
